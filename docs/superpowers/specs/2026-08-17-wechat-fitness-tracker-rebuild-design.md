# 微信健身记录小程序「牛来举铁」— 第一性原理重建设计（v2）

日期：2026-08-17
状态：已与用户确认整体方向（精简核心 + 干净重写）
取代：`docs/superpowers/specs/2026-08-16-wechat-fitness-tracker-design.md`

## 1. 重建动机（第一性原理）

该产品的第一性不是「做一堆页面」，而是三个动作连成的最短闭环：**记一次训练 → 看见进步 → 分享成果**。用户打开它，要的是「记下来、有成就感、能晒出去」。

上一版在真机上暴露的问题不是孤立 bug，而是按「功能清单」堆砌导致的系统性缺陷：

- 登录与建档拆成两页，引导被切碎；
- 模板训练、分享卡强依赖云端数据与画布，一旦加载失败整条链路中断；
- 样式用全局复用 + 内容盒模型，真机上宽度算错即全站横向漂移。

本版围绕一个总原则重建：**核心闭环最短、最可靠**。数据「按需加载 + 本地兜底」，样式「盒子模型统一 + 移动端优先」，非核心功能保留但架构上变成可裁剪的增量，不再压在主路径上。

## 2. 核心闭环（黄金路径）

1. 首次打开 → 判断是否已有档案 → 无则进入建档
2. 建档：隐私协议同意 → 性别 / 年龄 / 身高 / 体重 / 目标（每周频率可选）→ 计算体质指标 → 进入首页
3. 首页「开始训练」→ 记录页（自由训练或选模板）
4. 记录页录入 → 保存（本地兜底 + 云端）→ 完成
5. 完成后可选「生成分享卡」→ 分享页 → 保存相册 / 转发好友
6. 历史页、我的页查看进步与档案

## 3. 页面结构

共 6 个页面，底部导航改用微信原生 tabBar（4 个 Tab）。

| 页面 | 类型 | 职责 |
| --- | --- | --- |
| onboarding | 非 Tab | 首次建档，含隐私协议勾选、基础信息录入、体质指标结果 |
| home | Tab 首页 | 问候语、本周概览、开始训练、最近一次摘要 |
| record | Tab 训练 | 自由训练 / 模板训练、动作选择、按组录入次数与重量、底部总组数 / 总容量、完成保存 |
| history | Tab 历史 | 月历打卡、近 8 周趋势、PR 榜 |
| profile | Tab 我的 | 资料与指标、用户协议 / 隐私政策、注销账号 |
| share | 非 Tab | 训练完成后可选进入，生成分享卡 |

原生 tabBar 顺序：首页 / 训练 / 历史 / 我的。

相比上一版的 9 页，合并点：登录页并入 onboarding（openid 静默获取，不单独成页）；workout（模式选择）与 template（模板详情）并入 record；模板选择在 record 页内以半屏 / 弹层完成。

## 4. 数据模型（云数据库，4 个集合）

| 集合 | 字段要点 |
| --- | --- |
| users | openid、gender、age、heightCm、weightKg、goal（增肌/减脂/增力/保持）、frequency（1–7，可选）、bmi、bmiLevel、bodyFatRef、bmr、createdAt、updatedAt |
| workouts | openid、date、startedAt、endedAt、durationSec、mode、templateId（可选）、templateName（可选）、exercises[]、totalSets、totalVolume、createdAt |
| exercises | id、name、bodyPart、equipment、weighted、pcts（性别 + 新手 / 中级 / 高级的重量倍数区间）；全局只读种子 |
| templates | id、name、goal、genderHint（male / female / all）、frequency、exercises[]（exerciseId、sets、repRange）；全局只读种子 |

workouts.exercises[] 结构：`{ exerciseId, name, bodyPart, equipment, sets: [{ reps, weight }] }`。

PR（个人最好成绩）不再单独建集合，改由 stats 云函数从 workouts 现算；少一个需要同步的集合，少一类数据不一致的 bug。

## 5. 云函数（5 个）

| 云函数 | 职责 |
| --- | --- |
| login | 获取 openid，取 / 建用户记录并返回 |
| saveProfile | 写用户资料，服务端计算 BMI / 分级 / 体脂参考 / BMR 并回写 |
| catalog | 返回动作库与模板种子 |
| saveWorkout | 校验并保存训练记录，服务端计算 totalSets / totalVolume |
| stats | 首页本周概览、历史趋势、PR 现算 |

相比上一版去掉两个常驻函数：initDb（种子改为一次性初始化脚本）与 qrcode（分享卡小程序码推迟到 v1.5）。

推荐重量区间由前端 `utils/standards.js` 的纯函数计算（动作库只携带倍数规则），保证离线可用；云端 catalog 仅提供种子数据与未来增量更新。

## 6. 标准数据（中国标准为主）

- BMI = 体重(kg) / 身高(m)²；分级：<18.5 偏瘦、18.5–23.9 正常、24–27.9 超重、≥28 肥胖
- 体脂参考（中国常用健康参考值）：男性 <10% 偏瘦、10–20% 健康、20–25% 偏高、>25% 肥胖；女性 <15% 偏瘦、15–25% 健康、25–30% 偏高、>30% 肥胖
- BMR（Mifflin-St Jeor）：男 = 10×体重 + 6.25×身高(cm) − 5×年龄 + 5；女 = 10×体重 + 6.25×身高(cm) − 5×年龄 − 161
- 推荐重量区间：每个动作按「性别 + 体重倍数」分新手 / 中级 / 高级，男女标准不同；自重动作（引体、俯卧撑、卷腹、臀桥）不给出重量区间

## 7. 分享卡（v1，无小程序码）

- 默认版式 A 简约白卡（Notion 风格）：白底发丝线边框；顶部品牌名 + 「训练打卡」软标签；中间总容量大字；动作摘要（名称 + 每组重量×次数）；底部日期
- 可选自定义背景：从相册选照片作背景，自动叠加半透明深色遮罩并切换白色文字保证可读性
- 分享卡由小程序端 Canvas 本地绘制，不依赖网络
- 出口：保存到相册（发朋友圈）、转发好友（onShareAppMessage）
- 小程序码 → v1.5

## 8. 样式与真机适配

- 全局统一 `box-sizing: border-box`；页面级 `overflow-x: hidden`，禁止横向滚动
- 所有尺寸只用 rpx；底部 Tab 与固定按钮适配 `env(safe-area-inset-bottom)`
- 设计令牌（颜色 / 间距 / 圆角 / 字号）集中到 `app.wxss`，页面不硬编码
- 分享页隐藏画布用定位离屏（`position: fixed`），不参与布局宽度
- 底部导航用原生 tabBar，避免自定义组件带来的布局与状态维护成本

设计语言沿用项目根目录 `DESIGN.md`（Notion 风格：深海军蓝 Hero、紫色主按钮、粉彩卡片、发丝线卡片）。

## 9. 容错与健壮性

- 保存训练先写本地草稿再上云；云端失败保留草稿，下次启动自动补传
- 动作库 / 模板使用内置种子兜底，云端 catalog 失败不阻塞记录
- 分享卡本地绘制，canvas 初始化失败或相册权限被拒时给出明确提示并允许重试 / 跳过
- 输入范围校验统一抽到工具层（年龄 6–100、身高 80–250cm、体重 20–300kg、次数 1–100、重量 0–1000kg），前后端一致
- 训练中返回有防误退确认弹窗

## 10. 异常与安全

- 云数据库权限设为「仅创建者可读写」，查询严格按 openid 隔离
- 首次建档前展示并勾选用户协议 / 隐私政策，明示年龄、身高、体重的用途
- 我的页提供注销账号入口，不收集无关信息
- 网络异常不丢记录（本地草稿 + 自动补传）

## 11. 测试与验收

- BMI 分级边界、男女体脂参考、BMR 计算、推荐重量区间（不同性别 / 体重组合）

云函数测试：

- login 取 / 建用户、saveProfile 写资料与指标计算、saveWorkout 校验与统计、stats 概览 / 趋势 / PR

真机验收清单：

- 首次建档全流程、自由训练、模板训练、保存后历史可见、分享卡保存相册、断网草稿补传

## 14. 术语

- openid：微信用户的匿名唯一标识
- PR：Personal Record，个人最好成绩（最大重量 / 最重单次容量，现算得出）
- 总容量：一次训练中所有组「重量 × 次数」之和
- 体脂参考：根据身高、体重、性别估算的体脂率参考区间
